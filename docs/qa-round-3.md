## P1

- **R3-01 Under-13 lock is device-wide and permanent.** An adult who mistypes a 2016 date in "Edit: Born", or a child on a shared phone, locks onboarding for every later family profile (a grandparent added later lands on "TapStrong is for ages 13 and up"; /home → /welcome). Cause: `onboarding/who.tsx:51,:60`, `onboarding/ageBlock.ts`. Fix: the lock applies only to the self-signup "Me" flow before an account exists; it never blocks family profiles created by an adult owner; add an expiry (re-allow once the stored birth date turns 13) and a support path. Also: someone whose birthday is this month is treated as not yet having it (`age.ts:26`) — use the day when known, otherwise give the benefit of the month. Tests.
- **R3-02 Offline errors mislabelled.** supabase-js returns an error object instead of throwing, so the `offline` branch never runs. Owner sync (`account/cloud.ts:113-115`) says "Save your account first" to a saved account; PIN reset send/verify (`family/pinReset.ts:41,:57`) says "Something went wrong". Map network failures (status 0 / fetch error) to the offline copy. Tests.
- **R3-03 Home promises a workout that doesn't exist.** When everything is recovering, Home shows "FULL BODY · START · 60 MIN" and Start opens "Everything you picked is still recovering" (`(tabs)/home.tsx:58-63,:145`). Home must show the all-recovering state with Short mobility / balance / rest instead.
- **R3-04 48-hour gate too strict.** Training at the same time every other day (47.4 h) gets no workout; `groupReady` (`generate.ts:423`) needs the whole push/pull/legs group ready, so one recent muscle blocks the filler too. Use a tolerance (≥ 44 h adults, ≥ 90 h 60+, measured from session start, not `endedAt`), check readiness per muscle, not per group. Result expected: a 4-days/week user gets 4 workouts.
- **R3-05 Short mobility is 1 move / 8 min, always the same hip stretch.** The time fit (`generate.ts:546-554`, `:746-766`) trims `mobilityOnly` sessions. Should be warm-up + 3 moves + cool-down = 10 min, rotating focus (hips / upper back / shoulders / ankles). Done must say "Mobility done", not "Workout n", and Progress must not count it as a workout. Mobility stretches must not turn muscles red on the recovery map.
- **R3-06 Seniors have no Short mobility button** (`senior/SeniorHome.tsx`); add it. Senior Home minutes use the profile, not the session (`SeniorHome.tsx:40`).
- **R3-07 Swaps skip the safety dosing and the phase-1 exclusion.** `alternatives.ts:136-145` calls `doseFor` without `jointCare`; ramp-up is added after a swapped-in loaded lift without the check (`:173-176`). Laura in recovery phase 1 is offered "Airplane arm hold" (shoulder abduction, her painful movement). Apply the same filters and dosing on swap as in generation. Tests.
- **R3-08 Protected balance item bypasses recovery and titles the Home card.** `generate.ts:485` adds it with `family: []`, skips `isReady`, and its muscle feeds `sessionTargets` ("CALVES & GLUTES" while "Glutes still recovering"). Label it "Balance", keep it out of the card title and the recovery map, and swapping it must offer only balance moves.
- **R3-09 Loaded two-hand unilateral moves tagged `with_support` reach a faller.** Rosa (fell, osteoporosis) gets Dumbbell split squat with ramp-ups plus "hold a chair". Remove `with_support` from moves that need both hands for weights (`dumbbell_split_squat`, `dumbbell_single_leg_rdl`, similar); audit all.
